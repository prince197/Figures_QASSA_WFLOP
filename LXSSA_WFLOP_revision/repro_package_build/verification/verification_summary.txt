Verification of the SWEVO reproducibility package 1.0.0-rc (2026-10-04)
=========================================================================

Environment: CPython 3.11.15, NumPy 2.4.6, SciPy 1.17.1, pandas 3.0.6, Matplotlib 3.11.2, PyWake 2.6.20,
Linux x86_64 (Ubuntu 24.04), one worker process on a shared 4-core machine.

Procedure: the zip was built with make_package.sh, unpacked into a scratch folder, its checksums verified
(sha256sum -c MANIFEST.sha256: all files OK, manifest_check.txt), and then
    WITH_SLOW=1 WITH_DETERMINISM=1 WITH_PYWAKE=1 MANUSCRIPT=<SWEVO revision-2 latex_source> sh regenerate_all.sh <scratch>
was run in the unpacked package (total 569 s; regenerate_all_logs/steps.txt). Every step exited with 0.

Findings outside the package (reported to the authors, not changed here):
 a) The copies of the generated files in the revision-2 LaTeX folder (SWEVO_rev2/latex_source/analysis/) and the
    tables pasted into optA/sw/*.tex were edited by hand after generation: sentence-case captions, typography
    ($-$), wording ("ranked below the qualified methods"), spelling ("relabeling"), the GA row of tab:hr-site and the
    GA / analytic-gradient rows of tab:iea37 (all values traceable to rev2_summary.json). The package ships the
    unedited pipeline outputs.
 b) In SWEVO_rev2/latex_source/analysis/mpce_numbers.tex the timing macros were changed by hand
    (\NMsEvalMin/Max/SLSQP/PSO, \NSLSQPSlowdown = 0.24 / 0.47 / 1.82 / 0.24 ms and 7.5) and the text of
    08_beyond.tex and the supplement types these values; the pipeline generates 0.23 / 0.45 / 0.53 / 0.23 ms and 2.3
    (mpce_summary.json -> cost_per_eval), while the generated cost table tab:cost of mpce_supplementary.tex shows
    0.244-0.467 ms and 1.820 ms for MS-SLSQP. The macro definitions in mpce_numbers.py and the table use different
    timing summaries; the authors should decide which is quoted and make the macro and the table agree.
