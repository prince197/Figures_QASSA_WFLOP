# rev5: GA added to the re-evaluation studies (power curve / wake model, direction resolution)

Generated by `analysis/rev5_ga_reeval.py` (run 2026-10-28, `--procs 2`; logs reproduced below). No optimization was run, and no
existing record or generated file was changed. The only edit to an existing script is in `mpce_check_dir.py`: a new option
`--macros` and a pool-aware reference for F02. Its default behaviour is unchanged (rerun: 41/41 PASS, the same outcomes as `check_dir.log`).
Nothing under `SWEVO_rev2/latex_source/` was touched.

## 1. Procedure (identical to the other methods)

* **GA records:** `rev2_ga_s0of10.csv` ... `rev2_ga_s9of10.csv` (all 10 shards): 2,040 runs = 68 cases x seeds 1-30, 6,030
  evaluations, random initialization, of which 2,012 are feasible. They are read with `mpce_results.std_cols`, and duplicates on KEY
  are dropped with the last record kept, as in `rev2_analysis.read_rev2`.
* **Coordinates:** the stored run-record coordinates (3 decimals = 1 mm). The other methods use exactly these too:
  `mpce_robustness.reevaluate` and `mpce_direction.bench_reevaluate` read the `Coordinates` column of the run records
  (`fresh_*.csv`, `mpce_*.csv`), not the full-precision rerun captures `rev3_fullprec_*.csv`. Full-precision captures exist for
  only 3 GA records (`rev3_fullprec_rev2_ga.csv`: DS II r=500 N=3 seed 1; DS II 750/4 seed 7; DS II 1000/12 seed 20). As a side check,
  re-evaluating these 3 records at full precision changes the four model values by at most 4.5e-9 (relative), so they were not
  substituted.
* **(a) Power curve and wake model:**
  * Function: `mpce_robustness._reval`, unchanged. It evaluates the benchmark linear curve with Jensen, the cubic curve, the cubic curve
    with a 25 m/s cut-out, and the Gaussian wake (k* = 0.04) with the linear curve.
  * Caches: the eight methods' values come from `mpce_reevaluation_cache.csv`, which was only read (all 15,614 of their layouts were
    found in it). 1,920 new GA layouts were evaluated (Pool(2), chunksize 25) and stored in `rev5_ga_reevaluation_cache.csv`. The
    other 92 GA layouts have keys that were already in the cache: they are identical layouts, all with N = 2.
  * Cache check: 300 randomly drawn cached eight-method layouts were re-evaluated now, with a maximum relative difference of 4.5e-16.
  * Statistics: `mpce_robustness.robust_table` with `mpce_results.rank_rule`, unchanged. Runs per case and method are counted as in
    `mpce_results.robustness`.
  * Wake-model shift: `mpce_inference_extra.model_shift_block`, unchanged, called with the pool set to nine methods.
* **(b) Direction resolution:**
  * Functions: `mpce_direction.bench_reevaluate` and `bench_block`, unchanged. Each 15° bin is split into 1/3/15 sub-bins (Jensen)
    and 1/15 sub-bins (Gaussian). All 22,448 distinct feasible layouts (twelve methods) were re-evaluated.
  * Pools: the main pool is MAIN8 + GA. The component-analysis pool ABL9 is unchanged because GA is not a component variant.
  * Horns Rev, PyWake and IEA37 blocks were recomputed unchanged and are identical to `mpce_summary_dir.json`. GA's Horns Rev runs are
    handled in `rev3_sites.py`.
* **Reproduction checks:** the script first recomputes the eight-method pools from the same re-evaluations. They reproduce the
  stored results exactly:
  * `mpce_summary.json["robustness"]`: max |diff| 0.
  * `mpce_tab_robust_final.tex`: byte-identical.
  * `mpce_summary_extra.json["model_shift"]`: max |diff| 0.
  * `mpce_summary_dir.json["benchmark"]`, `["horns_rev"]` and `["iea37_projected"]`: max |diff| 0.
  * With GA, the 15° ranks equal the nine-method table `tab:farm-I-stats` (`rev4_farm_tables.json`). F02 checks this.
